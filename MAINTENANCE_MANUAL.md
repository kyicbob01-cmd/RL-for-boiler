# Industrial Boiler Control - Maintenance & Update Manual

## 1. Project Overview
This project implements a **Return-Conditioned Policy (RCP)** based DRL agent for optimizing industrial boiler control. The agent learns from a diverse set of rule-based expert strategies (SmartController) to minimize energy cost while satisfying temperature requirements across various load scenarios.

### Core Architecture
- **Algorithm**: Return-Conditioned Policy (Supervised Learning on Trajectories).
- **Input**: State Vector (5 dims) + Target Cost (1 dim).
- **Output**: Power Action (0-100%).
- **Training Method**: Offline RL using dataset generated by diversified SmartController variants.

## 2. Directory Structure (`Desktop/RL鍋爐`)
Only essential files are retained in the root directory.

| File | Description |
| :--- | :--- |
| `train_rcp.py` | **Main Training Script**. Handles data generation, training, and validation. |
| `compare_sc_rcp.py` | **Benchmark Script**. Compares the trained model (`rc_policy.pth`) against the rule-based baseline. |
| `boiler_env.py` | **Physics Engine**. Simulates the boiler thermodynamics and unit constraints. |
| `benchmark.py` | **Scenario Definitions**. Contains the standard 10 scenarios (S1-S10) used for testing. |
| `industrial_hmi_v2.py` | **HMI Application**. The GUI interface for human operators. |
| `rc_policy.pth` | **Active Model Weights**. The file generated by training and read by the HMI/Benchmark. |

## 3. Maintenance Procedures

### A. Training a New Model
1.  **Modify Configuration**: Open `train_rcp.py` to adjust parameters if needed.
    *   `num_episodes`: Increase for better coverage (Default: 10,000).
    *   `epochs`: Increase for deeper convergence (Default: 500).
2.  **Execute Training**:
    ```bash
    python train_rcp.py
    ```
    *   *Note*: This will overwrite `rc_policy.pth`. Back up previous models if necessary.

### B. Benchmarking and Validation
1.  **Run Comparison**:
    ```bash
    python compare_sc_rcp.py
    ```
2.  **Analyze Results**:
    *   **Cost**: Lower is better.
    *   **Wins**: RCP should win majority of scenarios, especially High Load (S2, S4, S6, S9).
    *   **S1 Check**: Ensure S1 performance does not degrade significantly (Cost < 9.0).

### C. Updating the Physics Model
If the physical boiler characteristics change:
1.  Edit `boiler_env.py`.
2.  Update constants in `BoilerPhysics` class (e.g., `HEAT_LOSS_RATE`, `MAX_POWER`).
3.  **CRITICAL**: You MUST retrain the model (`train_rcp.py`) after any physics change, as the old policy will be invalid.

## 4. Troubleshooting

| Issue | Probable Cause | Solution |
| :--- | :--- | :--- |
| **S1 Performance Drop** | "Survivorship Bias" | Check if failure filtering is active in `train_rcp.py`. |
| **Model Returns 0 Power** | Target Cost Too Low | Increase inference target cost in `compare_sc_rcp.py` (e.g., to 10.0 or 15.0).|
| **Training Crash (RAM)** | Dataset Too Large | Reduce `num_episodes`; verify memory usage. |

## 5. Deployment
To deploy the new model to the HMI:
1.  Ensure the new `rc_policy.pth` is in the same directory as `industrial_hmi_v2.py`.
2.  Restart the HMI application.
